Why you want this

👀 Front-end PRs you can SEE

A diff says what changed in the code; a before/after says what changed for the user. When every UI pull request ships with its pixels, review gets faster and "LGTM" means someone actually looked.

🪣 A photo album, by accident

Content-hashed keys, dated paths: every shot stays in your bucket forever. Six months in, you own what no git history gives you — what your app looked like, release by release. Retrospectives write themselves.

What's in the box

  • Capture — Bun.WebView: system WKWebView on macOS, your installed Chrome on Linux/Windows. Viewports, --wait-for, --scroll-to, --local-storage to boot authenticated screens.
  • Upload — Bun.S3Client: R2, AWS S3, MinIO, anything S3-compatible, configured by the standard S3_* env vars you already have.
  • URL out — bare URLs on stdout by default, --markdown for ready-to-paste ![caption](url) lines.
  • MCP in — cliche mcp serves screenshot and upload to any MCP client over stdio. Hand-rolled JSON-RPC, still zero dependencies.
  • Claude Code skill — a copyable PR-screenshots skill ships in the package.
